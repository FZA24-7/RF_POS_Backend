**Rule followed throughout:** Prisma and `@prisma/client` are always bumped
together, to the same exact version, never independently.

**Why ESLint uses the non-type-checked rule set:** `tseslint.configs.
recommended` (not `recommendedTypeChecked`) was chosen deliberately so `pnpm
lint` does not require cross-package type information - and therefore does
not require the generated Prisma Client to run. This is why linting could be
fully verified in this environment even while `@mafk/database` could not be
built. A follow-up hardening task once Prisma access is restored: switch to
`recommendedTypeChecked` for stricter guarantees.

## Production build (once unblocked)

```bash
pnpm db:generate
pnpm build                 # builds @mafk/shared, @mafk/validation, @mafk/database, then @mafk/api
node apps/api/dist/bin/server.js
```

## Electron / Windows build

Not attempted in Phase 1 (out of scope per the phased plan - see
`docs/RELEASE.md`). Electron 44.4.5 is pinned in the version matrix above so
Phase 7 does not need to renegotiate versions. Producing an actual
`MAFK-RetailFlow-POS.exe` additionally requires a Windows or Wine build host,
which this Linux sandbox does not have; that step will need to run on such a
host (or CI runner) regardless of the Prisma blocker.
